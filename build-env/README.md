# build-env — Сборочное окружение Active Directory Manager

## Что это

Это минимальный набор скриптов для сборки, тестирования и линтинга Android-проекта
Active Directory Manager без установки каких-либо инструментов на хост-машину.

Весь тулчейн — SDK, JDK, Gradle — живёт внутри Docker-образа `adm-build:local`.
На компьютере достаточно только Docker. Никаких дополнений в систему не требуется.

## Требования

- **Docker** (любая стабильная версия)
- ОС с поддержкой Docker (Linux, macOS, Windows)

Больше ничего ставить не нужно.

## Команды

Все скрипты лежат в папке `build-env/`. Запускать из корня проекта:

### `./build-env/build.sh`

Собирает APK-файл через Gradle (task `assembleDebug`).
Результат лежит здесь:
```
app/build/outputs/apk/debug/app-debug.apk
```

### `./build-env/test.sh`

Запускает юнит-тесты проекта (task `testDebugUnitTest`).
После выполнения показывает сводку из тестового репорта:
```
app/build/reports/tests/testDebugUnitTest/index.html
```

Можно передавать аргументы Gradle, например сузить набор тестов.

### `./build-env/lint.sh`

Запускает линтинг Android-проекта (task `lintDebug`).
Результат лежит здесь:
```
app/build/reports/lint-results-debug.html
```

## Первый запуск

Первая сборка образа может занять несколько минут — Docker скачивает SDK (~1.5 ГБ)
и собирает образ с нуля. Последующие запуски используют кеш и работают почти мгновенно.

Образ сохраняется локально и переиспользуется между сессиями. Если нужно обновить
сборку, удалите образ вручную: `docker rmi adm-build:local`.

## Кеш

Gradle кэширует артефакты в `build-env/.gradle/`. Папка создаётся автоматически
при первом запуске любого скрипта. Она добавлена в `.gitignore` и не попадает
в репозиторий.

При необходимости кеш можно удалить — последующие сборки просто потратят пару минут
на повторное скачивание зависимостей:
```bash
rm -rf build-env/.gradle/
```

## Переменные окружения

### `ADM_IMAGE`

Имя Docker-образа по умолчанию — `adm-build:local`. Можно переопределить:
```bash
ADM_IMAGE=adm-build:v2 ./build-env/build.sh
```

## Проброс аргументов

Все три скрипта пробрасывают оставшиеся аргументы в Gradle. Вот несколько примеров:

```bash
# Запустить конкретный тест через test.sh
./build-env/test.sh --tests '*LdapErrorMapperTest*'

# Запустить линтинг без печати стека (если не нужен)
./build-env/lint.sh -Plint.suppressAllWarnings=true

# Собрать release-версию (если настроена)
./build-env/build.sh assembleRelease
```

Любые флаги, которые поддерживает Gradle, можно передать напрямую.
